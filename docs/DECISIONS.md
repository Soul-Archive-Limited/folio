# Folio — Decisions

Every API and architecture decision, newest last. Format: date · phase · decision · why · source.

## Phase 0 — Setup (2026-10-25)

1. **Toolchain: Xcode 27.1 locally, iOS deployment target 26.0, Swift 6 language mode.** SPEC §0.2 says build with the latest installed SDK and gate anything newer than iOS 26 with `if #available`. Source: `xcodebuild -version` on the build Mac.
2. **CI uses the `macos-26` runner with its default Xcode (26.6).** GitHub's hosted image doesn't have Xcode 27 yet. Building against the iOS 26 SDK in CI also catches any iOS 27-only API that slips in without an `#available` check. Source: `actions/runner-images` macOS-26-arm64 README, 2026-10-25.
3. **gitleaks runs as a binary, not `gitleaks/gitleaks-action`.** The action needs a paid licence key for organisation-owned repos; the CLI is MIT-licensed and free. The CI job downloads a pinned release (v8.30.1) and checks its SHA-256 checksum. Source: gitleaks README and GitHub releases.
4. **The pre-commit hook lives in the committed `.githooks/` folder,** enabled with `git config core.hooksPath .githooks` via `scripts/setup-hooks.sh`. A hook in `.git/hooks` isn't versioned, so it wouldn't reach other clones.
5. **Signing team goes in `ios/project.yml` (`DEVELOPMENT_TEAM`), not in Xcode's UI.** The `.xcodeproj` is regenerated by XcodeGen and git-ignored, so a team picked in Xcode is lost on the next `xcodegen generate`. A Team ID isn't secret: it appears in every signed app.
6. **Licence: Apache-2.0 text in `LICENSE`, copyright line in `NOTICE`.** This is the standard Apache layout, and §4(d) of the licence carries `NOTICE` forward to anyone who redistributes the code. Trademark and name rights are reserved there too (SPEC §14.2).
7. **Dependabot covers `/api`, `/web` and GitHub Actions now.** The npm folders don't have a `package.json` until Phases 9 and 11. Until then Dependabot may log a "dependency file not found" error for them; it's harmless and goes away once the folders have a `package.json`.
8. **Swift concurrency defaults: `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` and `SWIFT_APPROACHABLE_CONCURRENCY = YES`.** These match Xcode 26+ new-project defaults and suit a UI-heavy app. Background work (crypto, sync, image processing) opts out explicitly with actors or `@concurrent`, as SPEC §0.11 wants.
9. **Placeholder app icon** is a 1024 px PNG drawn by a throwaway CoreGraphics script: page glyph and ember dot on ink (SPEC §3.10). It gets replaced by the Icon Composer `.icon` file when the owner supplies one.

## Phase 1 — Design system, greeting, privacy cover (2026-10-26)

10. **Liquid Glass API checked against Apple's docs via Context7 (`/websites/developer_apple_swiftui`).** `glassEffect(_:in:)` defaults to `.regular` in a capsule. `Glass` chains `.tint(_:)` and `.interactive()`. `GlassEffectContainer(spacing:)` blends and morphs its children. `glassEffectID(_:in:)` takes a `Hashable & Sendable` id plus a `Namespace.ID`. `ConcentricRectangle()` resolves its corners from the nearest `containerShape(_:)`. Button styles are `.glass`, `.glassProminent` and `.glass(_:)`. With a minimum of iOS 26, none of these need `#available` gates.
11. **Glass on content panels.** Apple's guidance reserves custom glass for controls. SPEC §3 deliberately puts glass on cards and on the calendar panel ("Quiet Glass"), and the owner's design wins. `FolioGlassModifier` is the single place glass gets applied, so this can be revisited in one file.
12. **Reduce Transparency fallback is explicit.** Glass becomes a solid `bgElevated` fill with a hairline border (SPEC §3.9). Increase Contrast adds the hairline on glass, and asset colours carry high-contrast variants for `inkSecondary`, `inkTertiary` and `hairline`. Verified in the Simulator via `com.apple.Accessibility EnhancedBackgroundContrastEnabled`.
13. **Selected chips use a solid fill, not tinted glass.** Tinted glass is translucent, so the label's contrast ratio couldn't be guaranteed. A solid category fill plus an auto-picked ink or white label always passes AA. The checkmark means selection doesn't rely on colour alone.
14. **Colour tokens live in `shared/design-tokens.json`; `scripts/generate-ios-colors.py` writes the asset catalog.** Phase 11's web CSS will read the same file. Generated asset symbols are on, so code says `.ember` or `Color(.ink)` and never uses hex.
15. **Category palette values were chosen and checked against WCAG AA.** All 24 light/dark variants are ≥ 4.5:1 against an ink or white label (worst case 4.69). Rose, ocean, teal and sage were darkened in light mode to get there. A unit test re-checks this at runtime.
16. **Type scale uses system text styles wherever SPEC sizes match the defaults** (largeTitle 34, title2 22, headline 17, body 17, subheadline 15 as `callout`, caption 12), so they follow Apple's Dynamic Type curve. `display` (56) and `micro` (10) have no system match and scale with `@ScaledMetric`.
17. **Aura blobs are radial gradients with a soft edge, not a live 90 pt Gaussian blur.** They look the same, and redrawing three blurred 300 pt circles at 30 fps would cost far more GPU time than the ≤ 2 % CPU budget in SPEC §3.5 allows. Drift is drawn in a `Canvas` inside `TimelineView(.animation(minimumInterval: 1/30, paused:))`. It's paused under Reduce Motion and when the app isn't active.
18. **Greeting word reveal uses a `TextRenderer`** that draws each tagged word with its own opacity and blur. It stays one `Text`, so wrapping, Dynamic Type and VoiceOver all behave normally.
19. **Every greeting has hand-written named and unnamed versions**, instead of string-stripping `{name}`. This reads naturally and localises cleanly. One small deviation: "Hey {name}, how's the day going?" becomes "Hey, how's the day going?" rather than "Hey how's…".
20. **The greeting timeline is driven by `Task.sleep` in `GreetingIntroModel`.** SPEC §4.2 gives absolute timestamps (0.15, 0.3, 0.6, 1.4 s), so a cancellable task is the clearest way to express them. Skip cancels the task and jumps straight to the dissolve.
21. **The privacy cover must also be applied at the root of every sheet and full-screen cover** (`.privacyCovered()`), because SwiftUI presents sheets above the window root's overlays. Phases 4+ must follow this for the composer and detail sheets.
22. **`@ViewBuilder`, not Xcode 27's `@ContentBuilder`.** CI builds with Xcode 26.6, which doesn't know the new name. They are the same type.
23. **DEBUG-only launch arguments for screenshots:** `-FolioScreen`, `-FolioNow` (fake local clock), `-FolioGreetingHold`, `-displayName`. They're compiled out of Release builds.
24. **Simulator testing note:** synthetic taps inside a `ScrollView` need a press of ≥ 0.2 s, or the scroll view's touch delay cancels them. This affects tooling only; real users aren't affected.

## Phase 2 — Data layer + encryption core (2026-10-27)

25. **SwiftData and CryptoKit APIs checked via Context7** (`/websites/developer_apple_swiftdata`, `/apple/swift-crypto`). `#Unique` and `#Index` (iOS 18+) go inside the `@Model`. `ModelContainer(for:migrationPlan:configurations:)` and `ModelConfiguration(schema:url:)` are used. `AES.GCM.seal(_:using:nonce:authenticating:)` and `HKDF<SHA256>.deriveKey(inputKeyMaterial:salt:info:outputByteCount:)` are the CryptoKit calls.
26. **The tombstone flag is `isTombstone`, not SPEC's `isDeleted`.** SwiftData's `PersistentModel` already defines `isDeleted` (the context's deletion state), so reusing the name would shadow it. The behaviour matches SPEC §5.
27. **Records that were never synced (`serverVersion == nil`) are hard-deleted.** Only synced records become tombstones awaiting the server's acknowledgement. Guest-mode deletes therefore leave nothing behind.
28. **`@Model` classes and pure value types are `nonisolated`.** The app module defaults to MainActor isolation, and SwiftData conformances must be nonisolated. Models stay non-`Sendable`, and `DiaryStore` uses them on the main actor only (write-swift §4).
29. **`??` inside `#Predicate` compiles but crashes in SQL generation** ("unimplemented SQL generation… bad LHS"). Optional key paths are compared against `[String?]` arrays instead. swiftdata-pro lists this family of runtime-only predicate failures.
30. **Schema v1 is a `VersionedSchema` with an empty `SchemaMigrationPlan`** from day one, so the first real migration is one new stage. The models live at top level for now; when v2 arrives, v1 gets frozen copies.
31. **The store directory is created with `NSFileProtectionComplete`** (and re-applied every launch), and the `com.apple.developer.default-data-protection` entitlement is set. Trade-off: SwiftData can't be read while the phone is locked. Phase 10's background refresh must only touch the network, or defer local writes until unlock.
32. **Photo pipeline:** ImageIO downsampling with `kCGImageSourceCreateThumbnailWithTransform` bakes orientation into the pixels. Images are re-encoded from pixels only, which strips **all** metadata, not just GPS. Output is HEIC at quality 0.75 (JPEG fallback if HEIC can't be encoded) plus a 240 px JPEG thumbnail at quality 0.7. It runs `@concurrent`, off the main actor.
33. **Folio Markdown is our own small, line-based dialect, not CommonMark.** Each line is one block. Italic is serialised as `_` so it never collides with `**`. Marker characters are always escaped. Unclosed markers stay literal. Canonical marker order (outermost first) is underline, highlight, strike, bold, italic. `RichDocument` is the shared model, and the editors (Phase 4 TextEditor, Phase 12 Tiptap) map to and from it. `shared/markdown-fixtures.json` (27 cases) pins both implementations, and a 200-case randomised round-trip test guards the iOS codec.
34. **`FolioCrypto` is a separate static framework with `nonisolated` default isolation.** It's library code with no SwiftUI dependency, and it's tested on its own (`FolioCryptoTests`).
35. **Crypto test vectors are generated with WebCrypto** (`scripts/generate-crypto-vectors.mjs`, Node), independently of CryptoKit, and the Swift tests must match byte for byte. The X25519 vectors use the RFC 7748 §6.1 keys, and the generated public keys and shared secret match the RFC's published values.
36. **Wire format:** AES-GCM output is `ciphertext ‖ tag`, as WebCrypto produces it, with the 12-byte nonce kept separately (matching SPEC §10.5's `ciphertext` and `nonce` fields). Associated data is `recordId|recordType|userId` with lowercase UUIDs. Record type raw values are frozen.
37. **Recovery key KEK uses HKDF-SHA256 with a random 32-byte salt** stored in the envelope (`info = "folio/recovery-kek/v1"`). A slow password KDF isn't needed because the key is 128 random bits. The envelope's associated data binds the user id.
38. **Device link uses X25519 → HKDF-SHA256 → AES-256-GCM, not HPKE.** The cryptokit skill suggests HPKE, but SPEC §10.3 restricts primitives to those both CryptoKit and WebCrypto have (WebCrypto has no HPKE). Salt = request id; info = `"folio/link/v1" ‖ newDevicePub ‖ senderPub`; associated data = `folio/link/v1|requestId|userId`.
39. **CryptoKit `SealedBox.ciphertext` is a slice with a non-zero start index.** Concatenating `ciphertext + tag` kept that offset and trapped on `data[0]`. `AESGCM.ciphertextAndTag(_:)` now always returns a fresh zero-based `Data`.
40. **Recovery key confirmation uses the last 4 characters of the 26-character key** (`confirmationSuffix`). The last display group has only 2 characters, so "the last 4 characters" means across the hyphen.
41. **The display name now lives in the synced `UserSettings` record** (SPEC §5), not `@AppStorage`. The DEBUG `-displayName` argument writes it there.
42. **gitleaks allowlist, narrow and documented in `.gitleaks.toml`:** `shared/crypto-vectors.json` (public test vectors only, never real keys), plus lines that are only Swift `Curve25519.KeyAgreement.PrivateKey` type annotations. Everything else is still scanned. The hook was not bypassed.

## Phase 3 — Tabs + Calendar (2026-10-27)

43. **TabView API checked via Context7.** `TabView(selection:)` with `Tab(_:systemImage:value:)` uses an `AppTab` enum (swiftui-pro: enums, not ints). `tabBarMinimizeBehavior(_:)` applies to the whole `TabView`, so it switches between `.onScrollDown` and `.never` by selected tab to limit minimising to Journal and To-do (SPEC §2).
44. **The floating "+" is a `Menu` with `primaryAction`.** Tap gives a new entry; long-press shows New entry / New task / Dictate (SPEC §2), with glass tinted ember. It's overlaid inside each tab's content, so the tab bar's safe-area inset (including minimising) positions it automatically.
45. **Composers are placeholders until Phases 4–5.** "+", day long-press, Write and Add task all open a half sheet that already uses the real presentation (`.medium/.large`, background interaction up to `.medium`).
46. **The collapse is a pinned grid over the day panel's scroll view, not two stacked views.** The panel scrolls with a top content margin equal to the full grid height, and the grid panel's height is `full − offset` (clamped to one week). The panel's top edge therefore stays glued to the grid's bottom edge and tracks the finger 1:1. Stacking the two views would have moved the content twice as fast as the finger.
47. **Collapse snapping uses a custom `ScrollTargetBehavior`**, so a flick keeps its momentum. Two measured gotchas: the target offset at rest is `-topMargin`, and `ScrollGeometry.containerSize` excludes the content margin. A short day therefore needs `minHeight = viewport + collapseDistance` to be able to collapse fully. `ScrollPosition.scrollTo(y:)` is in content coordinates excluding the margin.
48. **The month pager must keep its full height while the panel shrinks.** A horizontal `ScrollView` given less height centres its content vertically, which doubled the selected week's movement. The pager is now fixed at full height, pinned to the top and clipped by the panel.
49. **Endless paging:** ±240 months up front, extended by 120 months when within 12 of either end. A far jump (the Jump sheet reaches back to 1900) re-centres the list on the target instead of growing it. A unit test caught this when 1905 was unreachable.
50. **Collapsed state swaps to a dedicated week pager** (±260 weeks), which keeps the same weekday when swiping and updates the month title. The swap happens only at progress 1, where both show the identical row, so it's invisible.
51. **Thumbnails are cached in an `NSCache`** of up to 600 decoded `UIImage`s and decoded with `byPreparingForDisplay()` in a `@concurrent` function. Bytes are read from SwiftData on the main actor, which owns the context. Tiles have fixed frames and fade in, so nothing shifts.
52. **Selected photo days get a 3 pt ember frame drawn above the photo and task ring.** A filled square would hide the photo. Selected plain days use the filled ember square that springs from 0.6 to 1 (SPEC §3.6).
53. **Filtering fades the entire marker layer, photo tiles included, to 15%** on non-matching days (SPEC §6.2). Day numbers stay readable.
54. **At accessibility text sizes the calendar becomes a vertical list of days** with markers spelled out (SPEC §3.9 "week rows at AX sizes"). The month and year stack, and previous/next are icon buttons with spoken names. The VoiceOver rotor "Days with entries" is on the month pager.
55. **Performance budget is checked by a test** (`CalendarPerformanceTests`). With 10,000 entries and 5,000 photos, a month's markers compute cold in under 120 ms and read from cache in under 2 ms. The 120 fps Instruments pass is Phase 13.
56. **The "+" button's centre is 127 pt above the bottom edge on iPhone 17 Pro** (home indicator 34 + tab bar 49 + 16 + 28). The greeting mark travels to this point.
57. **Synthetic Simulator taps need ~0.15 s on Liquid Glass buttons and ~0.3 s inside horizontal scroll views.** This is a tooling quirk only, recorded so screenshot scripts don't misread it as a bug.
58. **The privacy cover only engages after the app has been active once.** A cold launch passes through `.inactive` before the first `.active`, and the cover was flashing "See you soon" over the launch greeting. A frame-by-frame look at the Batch A recording caught it.

## Batch A fixes — owner review (2026-10-27)

59. **Calendar is quieter.** The open-task ring is 1 pt `inkTertiary` (white at 75% on photo tiles, where `inkTertiary` would vanish). The all-done ring stays `done` green at 1 pt. Out-of-month days are only a faded number: no photo, dots, rings, checks or today dot.
60. **The filter fades every marker on non-matching days**, rings and checks included, in both the month grid and the week strip (`CalendarModel.matchesFilter`).
61. **The day panel ends above the floating "+"** (tab bar + button + 16 pt, `FloatingButtonMetrics.clearance`), with a 24 pt fade at its bottom edge. The last row scrolls fully clear, and the "+" can never cover a row, at rest or mid-scroll. This is stricter than a content inset alone, which still lets rows rest under the button.
62. **"+N" on a photo tile counts extra entries that day**, not extra photos (`DayMarker.extraEntryCount`).
63. **One selection haptic per gesture**, via a single `selectionHapticCount` trigger. A tap that also pages the month suppresses the page's haptic.
64. **The large-text list opens on the selected day** (today by default), and re-anchors when the month changes.
65. **First weekday follows the locale** (unchanged). All screenshots from Batch B on are taken in the en_GB region, so weeks start on Monday; `scripts/sim-shot.sh` passes `-AppleLocale en_GB -AppleLanguages (en-GB)`.

## Phase 4 — Composer + entry detail (2026-10-27)

66. **Rich text APIs checked via Context7 and the iOS SDK interface.** iOS 26's `TextEditor(text:selection:)` binds an `AttributedString` and an `AttributedTextSelection`. `transformAttributes(in:)` and `typingAttributes(in:)` drive the Aa popover, and `AttributedTextFormattingDefinition` with `ValueConstraint(for:values:default:)` limits the allowed values. `Font.Resolved` (`font.resolve(in: fontResolutionContext)`) exposes `isBold` and `isItalic`, which is how the editor's fonts are read back into Folio Markdown.
67. **Blocks in the editor are visible line prefixes** (`• `, `1. `, `☐ `, `☑ `, `▍ `), because SwiftUI's `TextEditor` has no list or quote paragraph styles. Headings are a larger, medium-weight font, so bold inside a heading stays detectable. Return continues a list, and Return on an empty item ends it. Consequence: a stored paragraph that literally starts with "1. " becomes a numbered item once it's edited on iOS. This is excluded from the editor round-trip test and documented here.
68. **The formatting definition constrains underline and strikethrough to single, the background colour to the highlight, and foreground colours to the prefix and quote colours.** Pasted text or system formatting therefore can't introduce styles outside SPEC §5.1. Fonts are normalised when saving.
69. **The composer opens without keyboard focus.** The keyboard lifts the sheet past the medium detent and would hide the calendar that SPEC §6.4 says stays visible and tappable. Tapping the page starts writing. While the sheet is at the medium detent, tapping a calendar day moves the entry there, with a date-pill animation and a selection haptic.
70. **The composer sheet uses `.thickMaterial`** instead of the default sheet glass, so the day panel doesn't show through the writing.
71. **"+" morphs into the composer** via `matchedTransitionSource` on the button and `.navigationTransition(.zoom)` on the sheet. Entry cards zoom into entry detail the same way.
72. **Drafts autosave every 2 s** to `Application Support/Folio/Drafts/composer.json`, written with `.completeFileProtection`. Text, day, time and category are drafted; photos aren't kept until the entry is saved. One draft is kept at a time, keyed to the entry being edited (or new). Saving or discarding clears it.
73. **Camera:** the glass explainer appears before the system prompt (SPEC §7), the prompt only at first use, and an alert with "Open Settings" if access was denied. The camera button is disabled (with an accessibility hint) on devices without a camera, such as the Simulator. `UIImagePickerController` is wrapped, since SwiftUI has no camera view.
74. **Delete with Undo restores from an `EntrySnapshot`** (text, day, category and photo bytes). Never-synced entries are hard-deleted, so Undo recreates the entry with new ids. Duplicate uses the same snapshot path.
75. **The detail carousel shows full-resolution images** decoded off-main, with the thumbnail underneath while they load. Pinch or tap opens a full-screen viewer (pinch 1–4×, double-tap, pan).
76. **Mic and ✦ are in the keyboard toolbar but disabled**, with accessibility hints, until Phase 8. "Dictate" from the "+" menu opens the composer for now.

## Phase 5 — To-do (2026-10-27)

77. **A tick writes to the store immediately; only the list move waits 1.2 s.** The calendar shows the task as done at once, and a tick isn't lost if you leave the tab during the pause. Tapping again during the pause, or Undo, reverts the store.
78. **The Undo toast appears at the tick and lasts 4 s.** It covers both the 1.2 s pause and the move, so one toast handles both cases (`TodoModel.undo`). Toasts now sit above the "+" and the quick-add bar.
79. **Quick add reads "today" or "tomorrow" only as a whole word at the start or end** (case and trailing punctuation ignored), so "Today's paper" stays as typed. English keywords are localisable via `String(localized:)`.
80. **Swipe actions:** leading is Done / Not done. Trailing is Delete (asks first only if the task has notes), Edit, and Date, which opens Today / Tomorrow / Next week / Pick a date… / Remove date. The same actions are in the context menu for VoiceOver and Switch Control users.
81. **Undated tasks reorder with `List.onMove`**, which works on iOS 26 (`reorderable()` is iOS 27+). Only undated tasks have a manual order (SPEC §6.7).
82. **UI test target `FolioUITests`** (XCTest, which UI automation requires) proves SPEC §5 end to end: ticking keeps a task on its calendar day, marked done, and only Delete removes it. Rows carry accessibility identifiers (`todo-row`, `day-task-row`) so the test can't match the hidden Calendar tab's copy.
83. **Bug found and fixed: "Erase data on this iPhone" didn't erase.** SwiftData's `context.delete(model:)` batch delete fails on the Entry → EntryPhoto inverse ("mandatory OTO nullify inverse") and only logs it. Erase now deletes object by object, and a test covers it.

## Phase 6 — Journal + Categories (2026-10-27)

84. **Journal sections are cached per store revision and filter** (`JournalModel`), so a 10,000-entry journal doesn't regroup on every redraw. The Timeline is a `LazyVStack` with pinned glass month headers.
85. **Photos masonry is three `LazyVStack` columns with greedy shortest-column placement** by aspect ratio, keeping columns within about one photo of each other. Tiles use the 240 px thumbnails, so they're slightly soft at 3×; a medium rendition can come in Phase 13 if needed.
86. **Covers and the detail carousel decode at display size** (`DisplayImageCache`: ImageIO downsampling, cost-limited `NSCache` of 120 MB) instead of decoding the full 2048 px image for a card. A clear 16:9 or 4:3 frame carries the size, because an `Image` would impose its own aspect ratio.
87. **"Write for a past day"** opens a new entry for yesterday with the date picker already open (back to 1900). The placeholder switches to "What do you remember about this day?".
88. **Categories manager:** `List.onMove` for reordering, swipe to delete with a confirmation that states what will happen ("3 entries and 2 tasks will keep their content and lose this category"), and tap to edit. The edit sheet has a live chip preview, the 12-swatch grid (selection shown with a checkmark, not only a ring) and "None" plus the 40 curated symbols. The "+" is disabled at 30. It's reachable from the Profile placeholder until Phase 7. Category filters now work on Calendar, Journal and To-do.

## Batch B wrap-up (2026-10-27)

89. **Bug found and fixed: the Undo button on toasts didn't take taps.** A toast overlay attached to the `TabView` draws above the tab content but doesn't receive touches, so a tap on Undo fell through to the list row underneath (a long press opened the row's menu). Toasts are now hosted inside each tab's content (`toastHost` per tab, sitting `FloatingButtonMetrics.toastBottomPadding` above the content bottom so they clear the "+"). `UndoToastUITests` covers it.
90. **DEBUG-only launch options for screenshots**: `-FolioTab`, `-FolioJournalMode photos`, `-FolioTodoFilter`, `-FolioOpen composer|composerLarge|taskComposer|entry|categories|categoryEdit`. They're compiled out of Release builds. The calendar's `NavigationStack` now has a model-owned `path` so an entry can be opened directly.
91. **Recordings are sped up and compressed** to stay under 1 MB (SPEC §18): the composer flow at 7.5×, the tick/undo flow at normal speed. `RecordingUITests` drives the tick/undo flow and is skipped unless `FOLIO_RECORDING=1`. UI test runs reset the simulator's data, so screenshots are taken after re-seeding with `-FolioResetData YES -FolioSampleData YES`.

## Batch B fixes (2026-10-27, owner review)

92. **The floating "+" lives only on the root screens of Calendar and Journal.** It materialises away (glass `.materialize` plus a 0.4 scale and fade on a spring; a plain fade under Reduce Motion) when an entry is pushed, and comes back on pop; each tab's `NavigationStack` path is model-owned so the shell can tell. To-do has no "+": the quick-add bar is full width with an expand button that opens the full task composer carrying whatever was typed (title and parsed date). The "+" long-press menu (New entry, New task, Dictate an entry) stays on Calendar and Journal.
93. **To-do bottom area:** the toast and the quick-add bar share one bottom safe-area inset, so the list's inset grows with them and the last row always scrolls clear of the bar and the tab bar. Behind the bar, a scrim fades from clear to the page colour over 60 pt and stays solid down through the tab bar.
94. **Toast placement:** on To-do, just above the quick-add bar; on Calendar and Journal roots, in the "+" row, leading-aligned with room left for the button; elsewhere (pushed screens, Profile), just above the tab bar. Toasts slide in and out on `.spring(duration: 0.45, bounce: 0.25)`, and only fade under Reduce Motion.
95. **Glass cards in horizontal scroll views share one `GlassEffectContainer`** ("Same day in other years", category chips). Separate glass shapes inside a scroll view showed a lighter band behind them.
96. **The selected category chip scrolls into view (centred) when a composer opens**, and again when the selection changes.
97. **Task composer:** focus goes to Title on open. Turning Date or Time on puts the keyboard away with a smooth animation, raises the sheet to `.large` and scrolls the picker fully into view. Picking a day or scrolling the form also dismisses the keyboard.
98. **Third photo rendition, "display": 1080 px long edge, HEIC at quality 0.6 (~150 KB)**, made in the same pipeline pass. Day cells keep the 240 px thumbnail; cards, the Journal grid and the composer strip use display; the detail carousel and full screen use the full image. `EntryPhoto.displayData` arrives in **schema v2** with a lightweight migration from a frozen copy of v1 (`FolioSchemaV1.Entry` / `.EntryPhoto`). The field is optional so the migration stays lightweight, and photos from v1 get their rendition from a background backfill after launch. Sync (Phase 9) uploads all three renditions from day one.
99. **Drafts keep photos.** New photos in a draft are written as files (full, display, thumbnail) in `Application Support/Folio/Drafts/Photos`, with `NSFileProtectionComplete` and the Drafts folder excluded from backup. Photos already on the entry are referenced by ID. All draft files are deleted when the draft is saved or discarded, and a photo removed from the strip loses its files on the next autosave.
100. **File protection and sync (decided for Phase 10):** the store and photos stay `NSFileProtectionComplete`. Sync only runs while protected data is available, in the foreground or in a background refresh while the device is unlocked. When the device is locked, sync skips cleanly (checks `UIApplication.isProtectedDataAvailable` and does nothing, with no error state) and catches up on the next unlock or launch.

## Phase 7 — Onboarding, tour, Profile (2026-10-27)

101. **Onboarding is a horizontal paging `ScrollView`**, not a page-style `TabView`, so the parallax can follow the scroll (`scrollTransition`: the art lags the page by about half, the text slightly; none under Reduce Motion). Buttons move pages with `ScrollViewReader.scrollTo`, because setting `scrollPosition` alone didn't always move a lazy stack, and taps are ignored while the pager is still moving. Completion is a device-only `@AppStorage` flag (`hasOnboarded`), not a synced setting: a new device onboards (and later unlocks) on its own.
102. **Sign-in buttons before Phase 10:** DEBUG builds show Apple, Google and email with an "Available after Phase 10" toast. Release builds show only Continue (guest mode), and the Profile Account card says the diary is on this iPhone only (`FeatureFlags.showsSignIn`). The Apple button is the system `SignInWithAppleButton(.continue)` (black in light mode, white in dark), clipped to a capsule. The Google button follows Google's branding rules: the official multicolour "G" as a vector asset, white fill with a #747775 outline (#131314 with #8E918F in dark mode), and "Continue with Google". Apple comes first (HIG).
103. **The guided tour is one `TipGroup(.ordered)`** held by `TourModel` in the environment. That gives six popover tips, one at a time: month grid (Next), today's cell (advances on a day tap), "+" (advances when a composer opens), the composer tool row (Got it, or closing the composer), the To-do tab and the Profile tab (each advances when the tab is opened). Every tip has "Skip tour".
