# Folio — Decisions

Every API and architecture decision, newest last. Format: date · phase · decision · why · source.

## Phase 0 — Setup (2026-10-25)

1. **Toolchain: Xcode 27.1 locally, iOS deployment target 26.0, Swift 6 language mode.** SPEC §0.2 says build with the latest installed SDK and gate anything newer than iOS 26 with `if #available`. Source: `xcodebuild -version` on the build Mac.
2. **CI uses the `macos-26` runner with its default Xcode (26.6).** GitHub's hosted image doesn't have Xcode 27 yet. Building against the iOS 26 SDK in CI also catches any iOS 27-only API that slips in without an `#available` check. Source: `actions/runner-images` macOS-26-arm64 README, 2026-10-25.
3. **gitleaks runs as a binary, not `gitleaks/gitleaks-action`.** The action needs a paid licence key for organisation-owned repos; the CLI is MIT-licensed and free. The CI job downloads a pinned release (v8.30.1) and checks its SHA-256 checksum. Source: gitleaks README and GitHub releases.
4. **The pre-commit hook lives in the committed `.githooks/` folder,** enabled with `git config core.hooksPath .githooks` via `scripts/setup-hooks.sh`. A hook in `.git/hooks` isn't versioned, so it wouldn't reach other clones.
5. **Signing team goes in `ios/project.yml` (`DEVELOPMENT_TEAM`), not in Xcode's UI.** The `.xcodeproj` is regenerated by XcodeGen and git-ignored, so a team picked in Xcode is lost on the next `xcodegen generate`. A Team ID isn't secret: it appears in every signed app.
6. **Licence: Apache-2.0 text in `LICENSE`, copyright line in `NOTICE`.** This is the standard Apache layout, and §4(d) of the licence carries `NOTICE` forward to anyone who redistributes the code. Trademark and name rights are reserved there too (SPEC §14.2).
7. **Dependabot covers `/api`, `/web` and GitHub Actions now.** The npm folders don't have a `package.json` until Phases 9 and 11. Until then Dependabot may log a "dependency file not found" error for them; it's harmless and goes away once the folders have a `package.json`.
8. **Swift concurrency defaults: `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` and `SWIFT_APPROACHABLE_CONCURRENCY = YES`.** These match Xcode 26+ new-project defaults and suit a UI-heavy app. Background work (crypto, sync, image processing) opts out explicitly with actors or `@concurrent`, as SPEC §0.11 wants.
9. **Placeholder app icon** is a 1024 px PNG drawn by a throwaway CoreGraphics script: page glyph and ember dot on ink (SPEC §3.10). It gets replaced by the Icon Composer `.icon` file when the owner supplies one.

## Phase 1 — Design system, greeting, privacy cover (2026-10-26)

10. **Liquid Glass API checked against Apple's docs via Context7 (`/websites/developer_apple_swiftui`).** `glassEffect(_:in:)` defaults to `.regular` in a capsule. `Glass` chains `.tint(_:)` and `.interactive()`. `GlassEffectContainer(spacing:)` blends and morphs its children. `glassEffectID(_:in:)` takes a `Hashable & Sendable` id plus a `Namespace.ID`. `ConcentricRectangle()` resolves its corners from the nearest `containerShape(_:)`. Button styles are `.glass`, `.glassProminent` and `.glass(_:)`. With a minimum of iOS 26, none of these need `#available` gates.
11. **Glass on content panels.** Apple's guidance reserves custom glass for controls. SPEC §3 deliberately puts glass on cards and on the calendar panel ("Quiet Glass"), and the owner's design wins. `FolioGlassModifier` is the single place glass gets applied, so this can be revisited in one file.
12. **Reduce Transparency fallback is explicit.** Glass becomes a solid `bgElevated` fill with a hairline border (SPEC §3.9). Increase Contrast adds the hairline on glass, and asset colours carry high-contrast variants for `inkSecondary`, `inkTertiary` and `hairline`. Verified in the Simulator via `com.apple.Accessibility EnhancedBackgroundContrastEnabled`.
13. **Selected chips use a solid fill, not tinted glass.** Tinted glass is translucent, so the label's contrast ratio couldn't be guaranteed. A solid category fill plus an auto-picked ink or white label always passes AA. The checkmark means selection doesn't rely on colour alone.
14. **Colour tokens live in `shared/design-tokens.json`; `scripts/generate-ios-colors.py` writes the asset catalog.** Phase 11's web CSS will read the same file. Generated asset symbols are on, so code says `.ember` or `Color(.ink)` and never uses hex.
15. **Category palette values were chosen and checked against WCAG AA.** All 24 light/dark variants are ≥ 4.5:1 against an ink or white label (worst case 4.69). Rose, ocean, teal and sage were darkened in light mode to get there. A unit test re-checks this at runtime.
16. **Type scale uses system text styles wherever SPEC sizes match the defaults** (largeTitle 34, title2 22, headline 17, body 17, subheadline 15 as `callout`, caption 12), so they follow Apple's Dynamic Type curve. `display` (56) and `micro` (10) have no system match and scale with `@ScaledMetric`.
17. **Aura blobs are radial gradients with a soft edge, not a live 90 pt Gaussian blur.** They look the same, and redrawing three blurred 300 pt circles at 30 fps would cost far more GPU time than the ≤ 2 % CPU budget in SPEC §3.5 allows. Drift is drawn in a `Canvas` inside `TimelineView(.animation(minimumInterval: 1/30, paused:))`. It's paused under Reduce Motion and when the app isn't active.
18. **Greeting word reveal uses a `TextRenderer`** that draws each tagged word with its own opacity and blur. It stays one `Text`, so wrapping, Dynamic Type and VoiceOver all behave normally.
19. **Every greeting has hand-written named and unnamed versions**, instead of string-stripping `{name}`. This reads naturally and localises cleanly. One small deviation: "Hey {name}, how's the day going?" becomes "Hey, how's the day going?" rather than "Hey how's…".
20. **The greeting timeline is driven by `Task.sleep` in `GreetingIntroModel`.** SPEC §4.2 gives absolute timestamps (0.15, 0.3, 0.6, 1.4 s), so a cancellable task is the clearest way to express them. Skip cancels the task and jumps straight to the dissolve.
21. **The privacy cover must also be applied at the root of every sheet and full-screen cover** (`.privacyCovered()`), because SwiftUI presents sheets above the window root's overlays. Phases 4+ must follow this for the composer and detail sheets.
22. **`@ViewBuilder`, not Xcode 27's `@ContentBuilder`.** CI builds with Xcode 26.6, which doesn't know the new name. They are the same type.
23. **DEBUG-only launch arguments for screenshots:** `-FolioScreen`, `-FolioNow` (fake local clock), `-FolioGreetingHold`, `-displayName`. They're compiled out of Release builds.
24. **Simulator testing note:** synthetic taps inside a `ScrollView` need a press of ≥ 0.2 s, or the scroll view's touch delay cancels them. This affects tooling only; real users aren't affected.
